# UART 命令处理与数据输出

## 一、项目背景

数码管适合显示少量数字，调试时间和温度数据时串口更直接。这份工程由 UART 中断接收命令，在主循环中解析 `time1` / `temp2`，再经 `printf()` 的查询发送路径输出数据。

## 二、硬件分析

- CT107D 板载 IAP15F2K61S2；工程在 Keil 中使用 `STC15F2K60S2 Series` 兼容目标。
- UART1 使用 P3.0 / P3.1 功能脚；`uart.c` 按 12 MHz 配置 Timer1，标注波特率为 9600 bps。与独立/矩阵键使用这些引脚时，要核对板上的键盘/串口切换设置。
- DS18B20 数据脚在代码中为 P1.4；DS1302 使用 P1.7（SCK）、P2.3（SDA）、P1.3（RST）。串口只负责对外通信，传感器和时钟各有独立 `.c/.h`。

## 三、软件设计

```text
main → System_Init（初始化输出、温度、RTC、UART、Timer2）
     → Data_Task（周期读取时间/温度；按标志发送）
     → Logic_Task（解析 time1 / temp2，处理接收超时）
UART 中断 4 → 把 SBUF 字节写入接收缓冲 R[]
Timer2 中断 12 → 维护接收超时、温度和时间计数
发送路径 → printf() 调用 putchar() → 写 SBUF 并查询 TI
```

`main.c` 负责缓冲和命令，`uart.c/.h` 负责波特率与发送，`onewire.c/.h`、`ds1302.c/.h` 各处理自己的器件；`1.uvproj` 使用这些文件的原相对路径。

## 四、关键代码分析

- `Uart_Init()` 配置 `SCON`、Timer1 重装值、串口中断和总中断。发送由 `printf()` 调用 `putchar()`：写入 `SBUF` 后查询等待 `TI`，不是发送中断驱动的队列。
- `Uart() interrupt 4` 收到 `RI` 后取走 `SBUF`，接收缓冲有效索引为 `R[1]` 开始。`Logic_Task()` 对照前 5 个字符识别 `time1` 或 `temp2`，分别设置发送标志。
- `Count_Recv` 在每个 Timer2 节拍增加，新字节到来时清零；超过约 100 ms 就清接收缓冲。`Data_Task()` 按标志输出时间或温度，而不是在接收中断里做传感器读取。

## 五、调试与验证

- **问题**：串口输出的时间容易被误认为当前真实时间。
- **现象**：代码中的 `System_Init()` 每次启动都会调用 `Set_Time(0x23, 0x59, 0x55)`，年份变量固定为 2026。
- **原因**：这是测试通信流程时写入的初始值，不是从外部校时得到的日期时间。
- **处理**：当前将 `time1` 作为命令—响应示例；若要实现真实时钟，再单独处理首次设时和上电保持，并测试重启前后输出。
- **经验**：串口“能发出字符串”与“数据语义正确”是两层验证。`putchar()` 等待 `TI`、串口 ISR 又处理 `TI`，发送边界也值得用实机连续命令测试。

用 Keil 打开 `1.uvproj`，串口工具按 9600 bps 分别发送 `time1`、`temp2`，记录命令接收与查询发送的输出。进一步的代码检查见 [调试记录](../../docs/调试记录.md)。

## 六、项目收获

这份程序把接收中断、超时计时、命令识别和数据采集放在不同位置。读代码时可以沿“中断收字节 → 主循环识别命令 → 设置标志 → 查询发送响应”追踪通信流程。
