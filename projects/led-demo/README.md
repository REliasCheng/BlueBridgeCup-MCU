# LED 与锁存器练习

## 一、项目背景

在 CT107D 上点亮 LED 不是单纯给某个 GPIO 写 0 或 1。LED、继电器和数码管共享 P0 数据口，必须先选对锁存通道。我用这份练习把端口输出、译码选择和 Timer2 节拍连起来；它也是后面所有显示和按键实验的基础。

## 二、硬件分析

- 开发板：CT107D；板载 MCU 为 IAP15F2K61S2。`2.1.uvproj` 使用 `STC15F2K60S2 Series` 兼容目标，Timer2 代码按 12 MHz 编写。
- P0 放置 8 位输出数据；P2.5～P2.7 送入 74HC138，再选通 74HC573。`0x80` 对应 LED 锁存通道，LED 为低电平有效。
- 程序还向 `0xA0` 通道写入继电器控制位，并用 `0xC0` / `0xE0` 更新数码管位选与段选。一个中断同时碰到多个锁存器，因此写 P0 和选 P2 的顺序很重要。

## 三、软件设计

```text
main → System_Init（关闭输出、启动 Timer2）
     → 循环执行 Logic_Task（更新位置、方向、继电器状态）
Timer2_Service（中断 12）→ 把当前状态送到 P0/P2 → 累加时间计数
```

`main.c` 管状态和输出，`library.c/.h` 放 Timer2 初始化。原工程使用独立的 `2.1.uvproj`，不依赖本仓库其他项目。

## 四、关键代码分析

- `Led_Bit` 表示当前 LED 位置；`P0 = ~(1 << (Led_Bit - 1))` 将目标位拉低，再用 P2 选 `0x80` 锁存。这里的取反不是装饰：LED 低电平才亮。
- `Flag_Direct` 决定位置递增还是递减；`Logic_Task()` 在 1～8 范围附近切换方向。`Count_Led`、`Count_Dsp`、`Count_Relay` 分别控制 LED、显示位和继电器变化节拍。
- `Timer2_Service()` 负责实际输出，主循环只更新状态。这种“中断负责节拍、主循环负责逻辑”的分工随后也用于数码管和综合工程。

## 五、调试过程

- **问题**：LED 位置往返时，边界值和 Timer2 中断可能交错。
- **现象**：静态阅读可见 `Logic_Task()` 修改 `Led_Bit`，中断同时用它计算移位；目前没有记录到板端异常。
- **原因**：主循环和中断共享状态，边界处理不能只看单个函数。
- **解决**：本次保留原学习代码；下一轮在板上观察 1、8 两端的输出，若出现异常再提交有复测记录的修改。
- **经验**：对 GPIO 演示也要检查时间顺序和边界值，不能只凭 0 error 判断行为。

打开 `2.1.uvproj`、核对 12 MHz 与板上设置后即可编译下载。原工程留有 0 error / 0 warning 构建记录；本仓库没有新增实物测试结论。

## 六、项目收获

这份代码把“P0 写数据、P2 选锁存器、Timer2 推进状态”三件事具体地对应起来。后续看数码管扫描或综合程序时，可以沿着同一条硬件路径读代码。
