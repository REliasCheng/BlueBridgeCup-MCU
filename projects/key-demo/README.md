# 独立按键与 LED 状态控制

机械按键会抖动，持续按下也不应在每次扫描时重复触发。这份工程把 P3 引脚状态交给 `Read_4Key()` 做按下确认，再由 `Key_Task()` 将键值映射为 LED 状态。

## 按键输入与 LED 输出

- CT107D 板载 IAP15F2K61S2；本工程用 P3.0～P3.3 读取 4 个独立键，用 P0/P2 的 `0x80` 锁存通道驱动 LED。
- `Read_4Key()` 将 P3.3、P3.2、P3.1、P3.0 分别映射成键值 4、5、6、7。主程序再用该键值选对应 LED。
- Keil 工程选用 `STC15F2K60S2 Series` 兼容目标，Timer2 初始化按 12 MHz、1 ms 节拍编写。P3.0/P3.1 也与 UART1 功能复用，综合项目要检查外设切换。

## 扫描流程

```text
main → System_Task（关输出、启动 Timer2）
     → Key_Task（按节拍调用 Read_4Key，更新 Led_Bit）
Timer2_Service → 输出 LED 位图并增加 Count_Key
```

扫描细节放在 `library.c`，应用层只处理键值与 LED 的对应关系，避免把 P3 的电平判断散落到主程序各处。

## 消抖与事件

- `Read_4Key()` 用静态变量 `count_press` 累积按下次数，达到 20 次并且 `flag_press` 仍为 0 时产生一次键值。松开后清计数与触发标志。按 1 ms 调用来理解，按下确认窗口约为 20 ms。
- `Key_Task()` 根据 4～7 的键值改变 `Led_Bit`；Timer2 中断把 `~(1 << (Led_Bit-1))` 写到 LED 锁存器。
- 当前代码实现**一次按下触发**。长按和双击需要增加按下时长、释放事件与重复触发规则。

## 输入检查

- **问题**：`Key_Task()` 中 `key_value` 可能在没有执行扫描分支时被读取。
- **代码现象**：`key_value` 只在 `Count_Key >= 1` 时赋值，后续 `if` 却无条件读取它。
- **原因**：局部变量的赋值路径和使用路径不一致。
- **处理**：先记录这条未赋值路径；板端分别测试无按键和四个按键，再依据结果修改判断范围或变量初始化。
- **经验**：按键调试要同时检查消抖状态、事件只触发一次，以及主循环每条路径上的变量有效性。

用 Keil 打开 `2.3.uvproj`，分别按四个键观察 LED 对应关系。更多记录见 [调试记录](../../docs/调试记录.md)。

原始引脚状态先转换成键值事件，再由应用逻辑决定 LED 行为。矩阵键可以沿用这条边界；长按和双击需要额外状态与测试。
