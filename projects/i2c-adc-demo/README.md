# PCF8591 I²C/ADC 练习

## 一、项目背景

CT107D 上的电位器、光敏等模拟量不能像按键那样直接用 GPIO 读成一个高低电平。PCF8591 把模拟输入转换为 8 位数字量；这份工程把软件 I²C、定时采样和数码管电压显示接到一起。

## 二、硬件分析

- 板载 MCU：IAP15F2K61S2；工程目标为 `STC15F2K60S2 Series` 兼容系列。
- `iic.c` 定义 P2.1 为 SDA、P2.0 为 SCL，软件控制起始、停止、8 位发送和接收。PCF8591 与 MCU 通过这两根线通信。
- 采样值最终仍通过 P0 数据口、P2 译码选通的数码管段选/位选锁存器显示。I²C 通信和数码管扫描使用不同任务位置，不能把较长的采样过程放进每一位的显示中断。

## 三、软件设计

```text
main → System_Init（关闭无关输出、预读 ADC、启动 Timer2）
     → Data_Task（按 Count_Adc 节拍更新 Volt）
     → Display_Task（将 Volt 转成两位小数的显示缓冲）
Timer2 中断 → 扫描数码管、累加 Count_Adc
```

`main.c` 只关心 `Volt` 和显示；`iic.c/.h` 封装 I²C 时序及 `Read_Adc()`，`library.c/.h` 管 Timer2 和锁存器控制。

## 四、关键代码分析

- `Read_Adc(0x43)` 先发送写地址 `0x90` 和控制字节 `0x43`，再重新起始、发送读地址 `0x91` 并接收一个字节。`0x43` 是本工程传给 PCF8591 的控制参数，不是测量出的电压。
- `main.c` 使用 `ADC 值 × 0.0196` 转换为 `Volt`，随后乘 100、取整拆位，在数码管上显示小数点。这个比例近似按 5 V 满量程换算，实际值仍取决于参考电压与输入接线。
- Timer2 把显示扫描和采样间隔分开：中断刷新显示，主循环按 `Count_Adc` 周期读 ADC，避免 I²C 时序直接占据显示刷新路径。

## 五、调试过程

- **问题**：显示出的“电压”是否能代表实际输入电压。
- **现象**：源码中的 `0.0196` 是固定换算系数；仓库目前没有同步的万用表对照读数。
- **原因**：数字量转电压必须知道参考电压、通道和量化范围，仅有 ADC 原始值不足以证明精度。
- **解决**：代码保留原比例。下一次板端测试记录输入电压、ADC 读值和显示值，再决定是否单独提交校准修改。
- **经验**：驱动读到字节、显示出数字和测量准确是三个不同的检查点。

打开 `3.1.uvproj` 可编译独立工程。原工程历史记录为 0 error / 0 warning；项目下一步是形成输入/显示对照表，而不是先改显示格式。

## 六、项目收获

这个项目把 P2.0/P2.1 的 I²C 时序、PCF8591 返回值和数码管显示串成一条数据链，也让我看到驱动封装与测量校准应分开讨论。
