# DS18B20 温度采集

## 一、项目背景

DS18B20 用单根 DQ 数据线完成复位、命令写入和温度字节读取。这份工程把 P1.4 上的 1-Wire 时序、温度换算和数码管刷新分在驱动与主程序中。

## 二、硬件分析

- CT107D 板载 IAP15F2K61S2；代码将 DS18B20 的 DQ 接在 P1.4。单总线要注意上拉、复位脉冲和采样窗口。
- 温度显示仍经 P0、74HC138/74HC573 的段选与位选锁存通道输出。传感器读取和数码管扫描共用 MCU 时间，不能让读温度阻塞显示过久。
- Keil 工程使用 `STC15F2K60S2 Series` 兼容目标，`library.c` 的 Timer2 参数按 12 MHz 写成。

## 三、软件设计

```text
main → System_Init（关无关输出、读取初值、启动 Timer2）
     → Data_Task（按 Count_Temp 周期更新 Temp）
     → Display_Task（温度 × 100，拆成数码管位）
Timer2 中断 → 逐位扫描显示并累加 Count_Temp
```

`onewire.c/.h` 保留复位、逐位读写和 `Read_Temp()`；`main.c` 只处理周期和显示；`library.c/.h` 提供锁存与定时器初始化。

## 四、关键代码分析

- `init_ds18b20()` 在 P1.4 上产生复位时序并读取存在脉冲；`Write_DS18B20()`、`Read_DS18B20()` 分别按位写入和读取。
- `Read_Temp()` 先发送 `0xCC`（跳过 ROM）与 `0x44`（启动温度转换），再复位并发送 `0xCC`、`0xBE` 读取温度寄存器的低、高字节。源码用 `0.0625` 把原始值换算为摄氏度。
- `Data_Task()` 约每 750 个 Timer2 节拍更新一次 `Temp`；显示函数把浮点数转换为百倍整数后拆位，使用段码的小数点位。

## 五、调试与验证

- **问题**：温度转换命令发出后何时读取结果。
- **现象**：静态阅读可见 `Read_Temp()` 发出 `0x44` 后紧接着复位和读取，没有单独等待转换完成或轮询完成标志；板端当前没有温度阶跃记录。
- **原因**：DS18B20 的转换需要时间，过早读取可能拿到旧值或不稳定值；具体表现需结合器件配置实测。
- **处理**：保留现有时序；记录上电首值、室温与加热后的连续读数和调用耗时，再判断是否需要拆开启动转换与读取步骤。
- **经验**：传感器驱动要分别检查总线时序、器件转换时间和上层采样周期，不能只看显示数值是否变化。

用 Keil 打开 `3.2.uvproj`；板端观察温度变化时，同时记录采样间隔与首次读数。

## 六、项目收获

这份代码让我把 DS18B20 的命令序列与 P1.4 上的逐位时序对应起来，并看到“750 ms 更新界面”与“单次温度转换完成”是两个不同概念。
