# 调试与代码检查记录

本页把“已经观察到”“仅从源码发现”和“尚待实物验证”分开。当前没有把猜测写成已解决的硬件故障。

## 记录 1：按键例程的局部变量

- 工程：[key-demo](../projects/key-demo/README.md)，`main.c` 的 `Key_Task()`。
- 发现方式：静态阅读代码，**不是板端故障记录**。
- 现象/疑点：`key_value` 仅在 `Count_Key >= 1` 分支中赋值，而分支后的 `if` 判断无条件读取它。若计数尚未到达，读取值可能未初始化。
- 当前处理：初版保留原始代码，不偷偷修改。待在 F 盘工作副本中复现并单独提交修订，同时记录按键实测行为。

## 记录 2：串口工程启动时写入固定时间

- 工程：[uart-demo](../projects/uart-demo/README.md)，`main.c` 的 `System_Init()`。
- 发现方式：静态阅读代码。
- 实际代码行为：启动流程调用 `Set_Time(0x23, 0x59, 0x55)`，会写入固定 RTC 时间；因此目前的串口时间输出不能直接作为真实当前时间证据。
- 当前处理：不改原始练习版本。板端复测时先确认 RTC 接线与写入行为，再考虑把初始化与时间设置分开。

## 记录 3：比赛训练工程的占位数据

- 工程：[16th-practice](../competition/national/16th-practice/README.md)，`main.c`。
- 发现方式：静态阅读代码。
- 实际状态：程序定义了 `temp`、`level`、`vol`、`wt` 等初始显示值和多个界面；不能据此声称真实传感器闭环或赛题功能已完整实现。
- 当前处理：标题使用“模拟训练工程”；逐项核对需求和实测结果后再写完成功能。
