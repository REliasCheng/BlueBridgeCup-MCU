# 蓝桥杯单片机竞赛训练：从模块到综合程序

这页把[省赛综合控制训练](../competition/province/integrated-control/README.md)与[国赛方向模拟训练](../competition/national/16th-practice/README.md)连起来，记录从单模块代码过渡到多外设控制、界面和任务组织的过程。

## 1. 基础模块为什么要先独立练

| 模块 | 仓库入口 | 到综合题时承担的任务 |
|---|---|---|
| GPIO/锁存器 | [LED](../projects/led-demo/README.md) | 状态灯、继电器、蜂鸣器输出；理解 P0/P2 共享总线 |
| 显示 | [数码管](../projects/segment-display-demo/README.md) | 数据页、参数页、提示信息；要求周期刷新而不挡主循环 |
| 输入 | [独立按键](../projects/key-demo/README.md) | 事件、消抖、界面切换；进一步过渡到矩阵键 |
| 通信 | [UART](../projects/uart-demo/README.md) | 命令输入与结果输出；要考虑缓存、超时和端口复用 |
| 模拟量 | [PCF8591](../projects/i2c-adc-demo/README.md) | ADC 输入、阈值判断前的数据采集和标定 |
| 温度 | [DS18B20](../projects/ds18b20-demo/README.md) | 周期测量与单位/小数处理；要给转换留时间 |

模块工程的价值不是文件可以直接复制进任何题目，而是能先确定每一条硬件—驱动—数据链，再在综合项目里安排它们的执行时机。

## 2. 省赛综合工程：先让数据和输出形成链路

[省赛综合控制训练](../competition/province/integrated-control/README.md)把 PCF8591、DS18B20、独立按键、数码管、LED、继电器和蜂鸣器放在同一工程。主循环分开处理显示缓冲、周期采样、按键事件与阈值判断；Timer2 中断负责扫描和计数。与单独的 ADC 或温度工程相比，关键变化是采样结果会进入 `Logic_Task()`，进而决定 LED 和继电器状态。

这条链路也给出具体的检查顺序：先确认 I²C/单总线读数，再确认换算与显示，最后确认阈值和输出。原驱动中尚有接收变量初值、温度转换等待等代码检查点，详见项目页；不能把模块接进同一 `main()` 就视作整机测试通过。

## 3. 遇到一题先做资源表

我会先把需求写成“输入 → 运算/状态 → 输出”，再列每项资源。以仓库的模拟训练代码为例：

| 资源 | 当前代码使用方式 | 集成时的检查点 |
|---|---|---|
| P0 + 74HC138/74HC573 | LED、数码管、蜂鸣器/继电器锁存输出 | 每次写 P0 前是否选对通道；扫描时是否先关位 |
| P3/P4 | `Read_16Key()` 矩阵扫描 | 行列状态与 UART1 的 P3.0/P3.1 是否冲突 |
| Timer2 | 1 ms 中断、显示刷新、`Count[]` 计时 | ISR 是否过长；主循环是否及时处理任务 |
| DS1302 | 周期读取 BCD 时间 | RTC 初始化是否每次都重设；时间如何转换和显示 |
| 参数数组 `ev[]` | 校准页的数值调整 | 数值边界、掉电保存和实际测量链是否存在 |

省赛或国赛题目的具体引脚、主频和功能会变，不能机械套一张固定资源表；但先做表能避免“驱动都能编译，组合起来却抢同一个端口或定时器”。

## 4. 程序分层：中断不替代业务逻辑

本仓库训练工程的主要流程：

```text
Timer2_Service（中断 12）
  ├─ 更新 LED/蜂鸣器/继电器锁存输出
  ├─ 数码管消影、段码、位选
  └─ Count[] 多个时间计数槽

main 循环
  ├─ Display_Task：按 ui/dm/pm/em 选择页面内容
  ├─ Key_Task：按键切换主/子页面与参数
  ├─ Data_Task：周期读取 DS1302
  └─ Logic_Task：按当前状态决定 LED/输出
```

`ui` 区分数据、参数、校准主页面；`dm`、`pm`、`em` 保存各页面下的位置。用状态变量管理显示，比在每个按键分支里直接写段码更容易查错。`Delay(num, time)` 使用不同 `Count[]` 槽给任务安排节拍，不需要给每个任务再占一个硬件定时器。

## 5. 从省赛控制到国赛方向的任务组织

- **省赛综合控制**：`integrated-control` 已把 ADC、温度和输入事件接到显示及输出判断上；调度主要依靠 Timer2 节拍和主循环。
- **国赛方向模拟**：`16th-practice` 把矩阵键、RTC、数据/参数/校准页面放到多计数槽框架中；温度、液位、体积、重量仍是固定初值，当前展示重点是界面与任务组织。
- **资源分配练习**：对照更复杂的测频、超声波和串口训练程序时，需要分别为 Timer0 外部计数、Timer1 UART 波特率、Timer2 周期扫描、PCA 测距建立资源表。本仓库现有的 `16th-practice` 并未实现这四路同时运行，不能把资源规划表写成它的运行结果。

这种分层让综合题从“驱动能否单独调用”推进到“共享端口与定时资源是否冲突、数据何时采样、状态何时输出”。

## 6. 国赛方向：先把硬件资源分开

当前[模拟训练工程](../competition/national/16th-practice/README.md)实际使用 Timer2、矩阵键和 DS1302；[UART 工程](../projects/uart-demo/README.md)另行演示 Timer1 波特率与接收中断。分析更复杂的测频/测距训练题时，我把资源用途列成下表，避免把每个驱动都默认交给同一个定时器：

| 资源 | 测频/测距/串口综合题中的分工 | 仓库内可核对的实现 |
|---|---|---|
| Timer0 | 接收 NE555 脉冲，按统计窗口计算频率 | 尚未收录为独立项目 |
| Timer1 | 为 UART1 提供波特率 | [UART 工程](../projects/uart-demo/README.md) |
| Timer2 | 1 ms 显示扫描和软件任务节拍 | [国赛方向模拟训练](../competition/national/16th-practice/README.md) |
| PCA 计数器 | 记录超声波回波等待时间 | 尚未收录为独立项目 |
| DS1302 | 通过独立的三线时序读取 RTC | [国赛方向模拟训练](../competition/national/16th-practice/README.md) |

资源表是设计分析，不代表上述功能已在一个仓库工程中全部运行。特别是 PCA 测距参考代码直接使用 `CH/CL/CR`，初始化条件、主频与超时换算都必须随具体工程核对。把这些边界分清楚，才能决定下一步是扩展已有工程，还是新增一个有独立测试记录的训练项目。

## 7. 国赛方向工程能展示什么

| 代码入口 | 已有实现 | 需要单独验证的部分 |
|---|---|---|
| `Display_Task()` / `Show_*()` | 根据 `ui/dm/pm/em` 生成数据、参数和校准页面内容 | 各页面的板端显示与切换 |
| `Read_16Key()` / `Key_Task()` | 扫描矩阵键并更新界面或参数状态 | 按键映射、消抖和边界值 |
| `Data_Task()` | 读取 DS1302 时间并转换 BCD | RTC 上电与连续运行的时间输出 |
| `temp/level/vol/wt` | 当前以固定初值参与页面显示 | 传感器采集与执行器控制尚需实现 |

原工程有历史构建记录；板端观察结果后续记入项目 README 和 [调试记录](调试记录.md)。
