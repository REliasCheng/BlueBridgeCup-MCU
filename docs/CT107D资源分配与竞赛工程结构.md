# CT107D 资源分配与竞赛工程结构

这份文档把仓库中的基础驱动、综合训练和 practice 修正版放到同一张资源表中。目标是在写综合题前先确定端口、定时器和通信接口的归属，再安排中断与主循环职责。

## 1. 板级共享通路

```text
IAP15F2K61S2 / STC15 兼容目标
  ├─ P0：8 位共享数据总线
  ├─ P2.5–P2.7：74HC138 通道选择
  │      └─ 74HC573 锁存：LED / ULN2003 / 位选 / 段选
  ├─ P2.0 / P2.1：软件 I²C（PCF8591 / AT24C02）
  ├─ P3.0 / P3.1：独立按键 S7/S6 或 UART1 RXD/TXD
  ├─ P1.4：DS18B20 DQ
  └─ P1.7 / P2.3 / P1.3：DS1302 SCK / SDA / RST
```

P0 上的数据必须和 P2 选中的锁存通道一起理解。`Control(0x80, value)` 与 `Control(0xE0, value)` 都会写 P0，但前者更新 LED，后者更新数码管段码。

## 2. 定时器与通信资源表

| 资源 | 仓库中的职责 | 使用工程 | 集成检查点 |
| --- | --- | --- | --- |
| Timer0 | 当前代表项目未独立占用 | 后续测频方向 | 与计数窗口、溢出中断和主频换算一起设计 |
| Timer1 | UART1 波特率 | `uart-demo`、`led-mode-training` | 不再用于其他周期任务；核对 12 MHz 配置 |
| Timer2 | 约 1 ms 系统节拍 | LED、数码管、按键和三个综合工程 | ISR 保持短小；显示扫描与任务计数共享节拍 |
| UART1 | 命令或状态报告 | `uart-demo`、`led-mode-training` | P3.0/P3.1 与 S7/S6 的板级切换关系 |
| 软件 I²C | PCF8591 ADC、AT24C02 参数 | `i2c-adc-demo`、`led-mode-training` | 地址、ACK、读末字节 NACK和共享总线时序 |
| 1-Wire | DS18B20 温度 | `ds18b20-demo`、省赛综合控制 | `0x44`转换与稍后读取必须分阶段 |
| DS1302 三线接口 | RTC 时间 | 两个国赛方向工程 | 启动读取与校时写入分开，避免复位覆盖时间 |

## 3. 软件职责分配

```text
Timer2 ISR
  ├─ 数码管关位 / 写段 / 开位
  ├─ LED、蜂鸣器、继电器锁存输出
  └─ Count[] / Count_Key 等软件节拍

main loop
  ├─ Key_Task：按键事件和页面状态
  ├─ Data_Task：ADC、温度、RTC等周期数据
  ├─ Logic_Task：阈值、模式和输出决策
  ├─ Display_Task：只生成显示缓冲
  └─ UART parser/report：在前台解析或组织报告
```

中断负责短周期、确定时序的动作；主循环负责协议解释、传感器事务和业务状态。UART 接收修正版遵循 `ISR → ring buffer → main parser`，避免在 ISR 中执行完整命令。

## 4. 三类工程如何递进

| 层级 | 目录 | 关注点 |
| --- | --- | --- |
| 基础驱动 | `projects/` | 单独确认锁存、显示、按键、UART、I²C 和 1-Wire 数据链 |
| 综合训练 | `competition/` | 将采样、显示、状态、参数和通信放进同一资源表 |
| 修正版实践 | `practice/peripheral-driver-corrections/` | 保留原版的同时修正确定的 ACK、等待、初始化和 ISR 职责问题 |

`competition/national/16th-practice` 中的 `temp`、`level`、`vol`、`wt` 是界面和任务训练使用的固定模拟数据；真实采集只有在接入对应驱动并形成板端记录后才成立。

## 5. 新题目的资源检查顺序

1. 把需求拆成输入、状态/计算和输出。
2. 为每个功能登记端口、锁存器、定时器和通信接口。
3. 先解决 P3.0/P3.1、P0/P2 等共享资源，再写业务流程。
4. 给显示、按键、采样和通信分配节拍，避免 ISR 中放长延时。
5. 单模块验证后再集成，每次只增加一条数据链。
6. 区分代码检查、Keil 构建、板端现象和测量精度四类证据。
