# CT107D 硬件分析：从端口到工程代码

我读 CT107D 程序时，先问三个问题：数据从哪个端口出去、当前选中哪个锁存器、外设实际接在哪个引脚。只盯着 `main()` 的业务循环，很容易漏掉 P0/P2 的共享关系。这页以仓库现有源码为例，把硬件和软件对上。

## 1. 开发板与目标器件

训练资料覆盖 CT107D V31、V40；板载 MCU 为 **IAP15F2K61S2**。本仓库的 Keil 项目选 `STC15F2K60S2 Series` 兼容目标，使用对应的 C51 寄存器定义。这是开发目标的名称，不表示板上的芯片型号变了。

V31 是绿色板、USB-B；V40 是黑色板、USB-C，部分跳线变成拨动开关。官方硬件版本说明要求：V40 下载 IAP15 时 J9、J14 都拨到 IAP15 侧。真正接线和下载前仍要核对手边板子的丝印。

## 2. P0/P2、74HC138 与 74HC573

```text
IAP15F2K61S2
 ├─ P0：共享的 8 位数据
 └─ P2.5 / P2.6 / P2.7：锁存通道地址
              ↓
          74HC138 译码
              ↓
          74HC573 锁存
              ├─ LED
              ├─ 蜂鸣器 / 继电器
              ├─ 数码管位选
              └─ 数码管段选
```

多个 `library.h` 将 `Control(x, y)` 写成“`P0 = y; P2 = x; P2 = 0`”的形式：`y` 是要锁存的 8 位数据，`x` 选择目标通道。原始练习的宏写法略有差别，但意图一致。P0 的一个数值本身没有固定含义；它被哪个锁存器接收，决定 LED、位选还是段选发生变化。

| P2 控制值 | 锁存对象 | 仓库里的例子 |
|---|---|---|
| `0x80` | LED | [LED 练习](../projects/led-demo/README.md)用低电平有效的位图点灯 |
| `0xA0` | 蜂鸣器、继电器等 | LED 练习按节拍切换继电器输出 |
| `0xC0` | 数码管位选 | [数码管练习](../projects/segment-display-demo/README.md)选择当前显示位 |
| `0xE0` | 数码管段选 | 根据 `Code[Bit[位号]]` 写入段码 |

**从代码追一次显示：**`Display_Task()` 将数字拆进 `Bit[]` → Timer2 中断先用 `0xC0` 关闭位选 → 用 `0xE0` 锁存当前段码 → 再用 `0xC0` 打开当前位。下一次中断换一位。这个顺序也解释了为什么多位显示需要定时刷新、为什么消影要放在换段之前。

## 3. 当前项目中的外设引脚

| 引脚/端口 | 对应外设 | 代码入口 | 阅读时注意 |
|---|---|---|---|
| P3.0～P3.3 | 独立按键 | [key-demo `Read_4Key()`](../projects/key-demo/library.c) | 按下确认后才产生键值，主循环负责 LED 响应 |
| P3/P4 行列 | 矩阵按键 | [训练工程 `Read_16Key()`](../competition/national/16th-practice/library.c) | 行列扫描与 UART1 引脚使用要结合板上切换方式 |
| P3.0 / P3.1 | UART1 收发 | [uart-demo `Uart_Init()`](../projects/uart-demo/uart.c) | 与按键用途复用，综合使用时先安排资源 |
| P2.0 / P2.1 | 软件 I²C SCL / SDA | [i2c-adc-demo `iic.c`](../projects/i2c-adc-demo/iic.c) | 起始、停止、收发字节由软件产生时序 |
| P1.4 | DS18B20 DQ | [ds18b20-demo `onewire.c`](../projects/ds18b20-demo/onewire.c) | 复位与采样窗口对主频和延时敏感 |
| P1.7 / P2.3 / P1.3 | DS1302 SCK / SDA / RST | [训练工程 `ds1302.c`](../competition/national/16th-practice/ds1302.c) | RTC 的 BCD 时间需转换后显示 |

表中的引脚是**当前源码实际使用**的连接定义；不代表所有版本板卡或所有赛题都以同样拨码状态运行。

## 4. Timer2 为什么是共用基础

本仓库多个工程按 12 MHz 把 Timer2 配成约 1 ms 中断。LED 工程用它推进位置与继电器计数；数码管工程每次中断切换显示位；按键工程用它触发周期扫描；[模拟训练工程](../competition/national/16th-practice/README.md)还用 `Count[]` 给多种任务分配节拍。**中断内做周期短、必须准时的事，主循环做状态判断与器件读写**，是这些代码共同的组织方法。

同时要注意共享数据：例如 `Count_Key` 在中断中增加、在主循环中清零；读写顺序需要通过实际运行和代码检查确认。编译通过只能说明语法/链接符合工程配置。

## 5. 实验与资料边界

这页的硬件关系依据 CT107D `SCH_V31.pdf`、`SCH_V40.pdf`、《硬件版本说明.txt》和仓库现有 C 文件整理；官方原理图与芯片手册没有复制到仓库。若要确认某个跳线、外设电源或版本差异，先查原图，再看实物丝印。下一步会补自己的开发板照片、引脚标注图和示波器/串口记录，目前不使用没有实测来源的图片。
