# CT107D 硬件分析：从端口到工程代码

我读 CT107D 程序时，先问三个问题：数据从哪个端口出去、当前选中哪个锁存器、外设实际接在哪个引脚。只盯着 `main()` 的业务循环，很容易漏掉 P0/P2 的共享关系。这页以仓库现有源码为例，把硬件和软件对上。

## 1. 开发板与目标器件

训练资料覆盖 CT107D V31、V40；板载 MCU 为 **IAP15F2K61S2**。本仓库的 Keil 项目选 `STC15F2K60S2 Series` 兼容目标，使用对应的 C51 寄存器定义。这是开发目标的名称，不表示板上的芯片型号变了。

V31 是绿色板、USB-B；V40 是黑色板、USB-C，部分跳线变成拨动开关。官方硬件版本说明要求：V40 下载 IAP15 时 J9、J14 都拨到 IAP15 侧。真正接线和下载前仍要核对手边板子的丝印。

## 2. P0/P2、74HC138 与 74HC573

```text
IAP15F2K61S2
 ├─ P0：共享的 8 位数据
 └─ P2.5 / P2.6 / P2.7：锁存通道地址
              ↓
          74HC138 译码
              ↓
          74HC573 锁存
              ├─ LED
              ├─ 蜂鸣器 / 继电器
              ├─ 数码管位选
              └─ 数码管段选
```

多个 `library.h` 将 `Control(x, y)` 写成“`P0 = y; P2 = x; P2 = 0`”的形式：`y` 是要锁存的 8 位数据，`x` 选择目标通道。原始练习的宏写法略有差别，但意图一致。P0 的一个数值本身没有固定含义；它被哪个锁存器接收，决定 LED、位选还是段选发生变化。

| P2 控制值 | 锁存对象 | 仓库里的例子 |
|---|---|---|
| `0x80` | LED | [LED 练习](../projects/led-demo/README.md)用低电平有效的位图点灯 |
| `0xA0` | 蜂鸣器、继电器等 | LED 练习按节拍切换继电器输出 |
| `0xC0` | 数码管位选 | [数码管练习](../projects/segment-display-demo/README.md)选择当前显示位 |
| `0xE0` | 数码管段选 | 根据 `Code[Bit[位号]]` 写入段码 |

**从代码追一次显示：**`Display_Task()` 将数字拆进 `Bit[]` → Timer2 中断先用 `0xC0` 关闭位选 → 用 `0xE0` 锁存当前段码 → 再用 `0xC0` 打开当前位。下一次中断换一位。这个顺序也解释了为什么多位显示需要定时刷新、为什么消影要放在换段之前。

表中的引脚对应当前工程源码；实际使用时按板型核对拨码状态。

### P3.0 / P3.1 的资源选择

P3.0、P3.1 在独立键扫描中对应 S7、S6，同时也是 UART1 的 RXD、TXD。键盘与串口共享引脚，V3.1/V4.0 的连接和切换方式不同；运行前按对应原理图、硬件版本说明和板上丝印选择通路。

单独按键工程使用P3.0～P3.3；UART命令工程将P3.0/P3.1交给串口。LED模式综合训练同时包含四键和UART报告，因此复测顺序应是：先确认板卡切换状态，再分别检查S6/S7与串口输出，最后决定是否调整键位或通信方案。代码层面的资源表不能替代板上开关状态。

## 4. Timer2 为什么是共用基础

本仓库多个工程按 12 MHz 把 Timer2 配成约 1 ms 中断。LED 工程用它推进位置与继电器计数；数码管工程每次中断切换显示位；按键工程用它触发周期扫描；[LED 模式训练](../competition/national/led-mode-training/README.md)用四步软件 PWM 调亮度；[多界面训练](../competition/national/16th-practice/README.md)用 `Count[]` 给任务分配节拍。**中断内做周期短、必须准时的事，主循环做状态判断与器件读写**，是这些代码共同的组织方法。

共享数据也要检查读写顺序：例如 `Count_Key` 在中断中增加、在主循环中清零。
