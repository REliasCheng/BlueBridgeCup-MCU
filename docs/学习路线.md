# 学习路线：从单模块到竞赛训练

这条路线按仓库已有的九个工程排列：先读硬件连接，再追踪驱动、主循环与中断之间的数据流，最后看多个模块如何共用时间和 I/O 资源。

```text
GPIO 与锁存器 → 数码管动态扫描 → 按键事件
       → UART 通信 → I²C/ADC 与 1-Wire 温度
       → 省赛采样/输出联动 → EEPROM/PWM/RTC 综合控制
       → 多界面、矩阵键与任务节拍的国赛方向训练
```

## 工程顺序

| 顺序 | 工程 | 已有代码中的技术链路 | 验证重点 |
|---|---|---|---|
| 1 | [LED 与锁存器](../projects/led-demo/README.md) | `Led_Bit` → P0 位图 → P2 `0x80` → LED | 往返边界、继电器周期 |
| 2 | [数码管动态扫描](../projects/segment-display-demo/README.md) | 数值拆位 → `Bit[]` → `Code[]` → Timer2 位扫描 | 段码、重影、刷新效果 |
| 3 | [独立按键](../projects/key-demo/README.md) | P3 输入 → `Read_4Key()` 按下确认 → `Key_Task()` → LED | 按下/松开、抖动与局部变量问题 |
| 4 | [UART 命令](../projects/uart-demo/README.md) | 接收中断 → 缓冲/命令 → 主循环 `printf()` 查询发送 | `time1`、`temp2`、连续输入边界 |
| 5 | [PCF8591 ADC](../projects/i2c-adc-demo/README.md) | P2.0/P2.1 I²C → 8 位 ADC 值 → 电压换算 → 显示 | 参考电压和万用表对照 |
| 6 | [DS18B20 温度](../projects/ds18b20-demo/README.md) | P1.4 单总线 → 温度原始字节 → 摄氏度 → 显示 | 转换等待、首值、连续采样 |
| 7 | [省赛综合控制](../competition/province/integrated-control/README.md) | ADC/温度/按键 → 显示缓冲与阈值判断 → LED/继电器/蜂鸣器 | 原始读数、显示与输出是否一致 |
| 8 | [LED 模式综合训练](../competition/national/led-mode-training/README.md) | 按键编辑参数 → EEPROM 保存 → 模式运行；ADC → PWM 亮度 | 掉电参数、亮度分档、串口报告 |
| 9 | [国赛方向模拟训练](../competition/national/16th-practice/README.md) | 矩阵键/RTC/计数器 → 多页面状态 → LED/数码管 | 页面切换与任务节拍 |

每个项目页都能从任务入口追到相应的驱动与硬件输出。综合工程不再按外设数量排序，而看输入数据是否进入状态判断、参数是否能保存、周期任务能否互不阻塞。

## 为什么这样排序

1. **先看输出**：LED 最容易把 P0 数据与 P2 锁存选通对应起来，数码管再把相同总线变成周期扫描。
2. **再加输入**：按键引入消抖、事件和状态更新；当前例程只做到一次按下确认，短按释放、长按和双击要继续写状态机。
3. **分清两类通信**：UART 面向电脑的字节流，I²C 面向板上器件的起始/地址/应答时序；DS18B20 又是时间更敏感的 1-Wire。
4. **再做省赛整合**：ADC 和温度进入显示及输出逻辑，按键改变蜂鸣器状态；检查采样、阈值和锁存输出这条链是否闭合。
5. **最后看国赛方向的系统组织**：LED 模式工程引入 EEPROM、PWM、RTC 和 UART 报告；多页面工程用矩阵键、`Count[]` 与 Timer2 组织界面和任务。
