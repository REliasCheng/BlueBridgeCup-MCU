# 实践路线：从单模块到竞赛训练

这是一条九步概念阅读路线，按板级资源与外设问题递进；早期九个完整训练工程的源码不在当前公开仓库。当前可直接检查的代码入口是 [外设独立实践](../practice/peripheral-driver-corrections/README.md)，不能把下表当作可运行项目清单。

```text
GPIO 与锁存器 → 数码管动态扫描 → 按键事件
       → UART 通信 → I²C/ADC 与 1-Wire 温度
       → 省赛采样/输出联动 → EEPROM/PWM/RTC 综合控制
       → 多界面、矩阵键与任务节拍的国赛方向训练
```

## 工程顺序

| 顺序 | 主题 | 技术分析链路（非当前完整工程） | 待验证重点 |
|---|---|---|---|
| 1 | LED 与锁存器 | `Led_Bit` → P0 位图 → P2 `0x80` → LED | 往返边界、继电器周期 |
| 2 | 数码管动态扫描 | 数值拆位 → `Bit[]` → `Code[]` → Timer2 位扫描 | 段码、重影、刷新效果 |
| 3 | 独立按键 | P3 输入 → `Read_4Key()` 按下确认 → `Key_Task()` → LED | 按下/松开、抖动与局部变量问题 |
| 4 | UART 命令 | 接收中断 → 缓冲/命令 → 主循环 `printf()` 查询发送 | `time1`、`temp2`、连续输入边界 |
| 5 | PCF8591 ADC | P2.0/P2.1 I²C → 8 位 ADC 值 → 电压换算 → 显示 | 参考电压和万用表对照 |
| 6 | DS18B20 温度 | P1.4 单总线 → 温度原始字节 → 摄氏度 → 显示 | 转换等待、首值、连续采样 |
| 7 | 省赛综合控制 | ADC/温度/按键 → 显示缓冲与阈值判断 → LED/继电器/蜂鸣器 | 原始读数、显示与输出是否一致 |
| 8 | LED 模式综合训练 | 按键编辑参数 → EEPROM 保存 → 模式运行；ADC → PWM 亮度 | 掉电参数、亮度分档、串口报告 |
| 9 | 国赛方向模拟训练 | 矩阵键/RTC/计数器 → 多页面状态 → LED/数码管 | 页面切换与任务节拍 |

下表用于组织阅读，不证明完整固件、输入输出闭环或板端效果。分析综合系统时，应分别核对输入是否进入状态判断、参数是否真实持久化、周期任务是否互不阻塞。

## 为什么这样排序

1. **先看输出**：LED 最容易把 P0 数据与 P2 锁存选通对应起来，数码管再把相同总线变成周期扫描。
2. **再加输入**：按键引入消抖、事件和状态更新；当前例程只做到一次按下确认，短按释放、长按和双击要继续写状态机。
3. **分清两类通信**：UART 面向电脑的字节流，I²C 面向板上器件的起始/地址/应答时序；DS18B20 又是时间更敏感的 1-Wire。
4. **再做省赛整合**：ADC 和温度进入显示及输出逻辑，按键改变蜂鸣器状态；检查采样、阈值和锁存输出这条链是否闭合。
5. **最后看国赛方向的系统组织**：LED 模式工程引入 EEPROM、PWM、RTC 和 UART 报告；多页面工程用矩阵键、`Count[]` 与 Timer2 组织界面和任务。

## 板端验证重点

优先记录独立按键的四键映射、UART 连续命令、PCF8591 输入与显示对照、DS18B20 转换等待，以及综合工程的阈值输出和 EEPROM 断电保持。记录板型/拨码、输入动作、实际输出；修改代码时再补同条件复测。

具体代码检查点见 [调试记录](调试记录.md)。
