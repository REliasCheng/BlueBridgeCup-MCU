# 学习路线：从单模块到竞赛训练

这条路线按仓库里能直接打开的工程排，不按资料包目录排。读每个项目时先找硬件连接，再看中断/主循环分工，最后核对输入和输出。一个功能“写进了 C 文件”与“在板上稳定工作”分别记录。

```text
GPIO 与锁存器 → 数码管动态扫描 → 按键事件
       → UART 通信 → I²C/ADC 与 1-Wire 温度
       → 多界面、RTC、任务节拍的竞赛模拟训练
```

## 为什么这样排序

1. **先看输出**：LED 最容易把 P0 数据与 P2 锁存选通对应起来，数码管再把相同总线变成周期扫描。
2. **再加输入**：按键引入消抖、事件和状态更新；当前例程只做到一次按下确认，短按释放、长按和双击要继续写状态机。
3. **分清两类通信**：UART 面向电脑的字节流，I²C 面向板上器件的起始/地址/应答时序；DS18B20 又是时间更敏感的 1-Wire。
4. **最后做集成**：训练工程不是把文件合并一下，而是要安排共享端口、定时器、显示刷新、按键扫描与业务状态。

## 下一次实验怎样留下证据

每个工程至少补四项：板型与连接/拨码、Keil 构建结果、输入动作、实际输出。若修改代码，再补“原现象 → 修改提交 → 复测现象”。这样 README 里的功能表可以从静态代码说明逐渐变成可核实的实验记录。

目前最值得先做的是：独立按键四键映射与消抖复测、UART 连续命令收发、PCF8591 与万用表对照、DS18B20 转换等待。具体代码疑点在 [调试记录](调试记录.md)。
