## 01 按键 `key_value` 的有效性

- **问题**：[独立按键工程](../projects/key-demo/README.md)的 `Key_Task()` 中，局部变量在某些调用路径上可能未赋值。
- **现象**：`key_value = Read_4Key()` 位于 `Count_Key >= 1` 分支内，后面的 `if(key_value == 4/5/6/7)` 在分支外。静态检查就能找到这条路径；暂无板端误触发记录。
- **原因**：扫描时机判断与键值处理范围没有保持一致。
- **解决**：保留初版源码，下一轮先按四键和无按键两类输入复测；若确认问题，再单独提交变量初始化或分支调整，并记录前后输出。
- **经验**：消抖阈值正确并不保证按键任务正确，必须检查每次进入 `Key_Task()` 时键值是否有效。

## 02 UART 输出与 RTC 时间语义

- **问题**：[UART 工程](../projects/uart-demo/README.md)能按 `time1` 输出字符串，但输出内容并不自动代表当前时间。
- **现象**：`System_Init()` 调用 `Set_Time(0x23, 0x59, 0x55)`；`Year` 在源码中固定为 2026。
- **原因**：当前版本先演示串口命令与 RTC 读取，没有实现“仅首次启动设时”或外部校时流程。
- **解决**：项目页明确说明它是通信练习。实测时检查重启前后 RTC 数据，再决定如何分开初始化与校时。
- **经验**：串口打印正确、RTC 寄存器可读、时间具有现实意义是三项不同的验收内容。另需测试连续发送命令时 `putchar()` 与串口 ISR 对 `TI` 的处理顺序。

## 03 ADC 数值到电压的换算

- **问题**：[PCF8591 工程](../projects/i2c-adc-demo/README.md)使用固定 `0.0196` 系数把 8 位读数转为电压。
- **现象**：代码能算出并显示数值，但仓库没有输入电压、参考电压和显示值的同步记录。
- **原因**：固定系数隐含满量程假设；实际精度由参考电压、输入通道和量化误差共同决定。
- **解决**：暂不把显示数值称为已校准电压。板上使用万用表取几个输入点，形成 `输入 V / ADC 原值 / 显示 V` 对照表，再决定是否改系数。
- **经验**：先验证 I²C 收发，再验证数据换算，最后验证测量精度，三个层次不能混成一个“驱动成功”。

## 04 DS18B20 转换等待

- **问题**：[DS18B20 工程](../projects/ds18b20-demo/README.md)的 `Read_Temp()` 在发送 `0x44` 后紧接着重新复位并读取。
- **现象**：代码没有单独的转换完成等待或轮询路径；目前没有上电首值、室温和加热后的连续读数记录。
- **原因**：温度转换不是瞬时完成；过早读取可能得到旧值或不稳定值，实际表现还与器件配置有关。
- **解决**：保留原代码进行温度阶跃与调用耗时复测；确认后在独立提交中调整“启动转换/等待/读取”的时序。
- **经验**：界面每 750 ms 更新一次，不等于一次 `Read_Temp()` 内部已经等够转换时间。

## 05 综合训练工程的完成范围

- **问题**：[国赛方向模拟训练](../competition/national/16th-practice/README.md)有数据、参数、校准界面，但不能只凭界面数量判断赛题完成度。
- **现象**：`temp`、`level`、`vol`、`wt` 使用固定初值；`Logic_Task()` 把蜂鸣器和继电器保持关闭。DS1302 时间读取和按键页切换则有实际代码路径。
- **原因**：当前版本主要搭建交互状态与任务框架，测量输入和执行器逻辑尚未形成有证据的闭环。
- **解决**：按“模拟训练”命名，并把已有界面、固定值和未实现项分开列出。之后逐项写需求、输入、预期输出、板端结果与修订提交。
- **经验**：竞赛工程的验收单位是需求项，不是源文件数量、界面数量或 Keil 的 0 error。

## 下一次板端调试怎么记

每条新记录写清：日期/板型和主频 → 操作或输入 → 实际现象（照片、串口输出、测量值）→ 代码定位 → 修改提交 → 同条件复测。没有测量数据时就写“代码检查”，有测量数据再写“实物结果”；这样提交历史才会对应真实工程进展。
