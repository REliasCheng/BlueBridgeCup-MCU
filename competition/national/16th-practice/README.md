# 国赛方向模拟训练工程

综合训练同时处理显示刷新、矩阵按键、RTC 读取、参数页和输出状态。这份国赛方向模拟工程将界面状态放在主循环、周期扫描放在 Timer2 中断，用现有程序练习任务分工与资源安排。

与[省赛综合控制训练](../../province/integrated-control/README.md)相比，这份工程更侧重多页面和矩阵键状态管理；省赛工程中的 ADC/温度采样与执行输出没有直接出现在本工程的测量链中。

## CT107D 资源

| 资源 | 本工程中的作用 |
|---|---|
| CT107D / IAP15F2K61S2 | 主控平台；`16.uvproj` 选用 `STC15F2K60S2 Series` 兼容目标 |
| P0 + P2.5～P2.7 + 锁存器 | LED、蜂鸣器/继电器、数码管位选和段选共用数据通路 |
| P3/P4 键盘引脚 | `Read_16Key()` 扫描矩阵键并返回键值 |
| DS1302 | 代码使用 P1.7 / P2.3 / P1.3 作为 SCK / SDA / RST，读取时分秒 |
| Timer2 | 约 1 ms 中断，负责显示刷新和多个任务计数 |

这个表也是综合程序的资源检查单：一个端口同时服务多个功能时，不能只看某个单独驱动是否通过编译。

## 任务与页面流程

```text
main → System_Init（状态、显示、RTC、Timer2）
     → Display_Task（根据 ui/dm/pm/em 选择显示内容）
     → Key_Task（矩阵键改变界面或参数）
     → Data_Task（周期读取 DS1302）
     → Logic_Task（根据当前界面更新 LED/输出状态）
Timer2_Service → 刷新锁存器与数码管；推进 Count[0..8]
```

`main.c` 是任务和界面状态的集中入口；`library.c/.h` 放 Timer2 与 `Read_16Key()`；`ds1302.c/.h` 负责 RTC 读写。`16.uvproj` 可按原相对路径打开这些文件。

## 状态、显示与时序

- `ui` 用 `DATA`、`PARA`、`CALIB` 区分数据、参数和校准三类主界面。`dm` 再在时间、液位、电压、重量数据页间切换；`pm`、`em` 指向参数项和校准点。`Display_Task()` 只根据状态调用对应 `Show_*()`，不直接扫描数码管。
- `Key_Task()` 中键值 4 切主界面、5 切子界面，8/9 在校准页调整 `ev[em]`。`Read_16Key()` 把 P3/P4 行列状态转换成键值，并用计数做按下确认。
- `Timer2_Service()` 每次先更新 LED、蜂鸣器/继电器锁存通道，再执行数码管“关位 → 写段 → 开位”，最后增加 `Count[]`。`Delay(num, time)` 让不同任务使用各自计数槽，而不是每个功能再占一个硬件定时器。
- `Data_Task()` 读取 DS1302 的时分秒并转换 BCD；`Logic_Task()` 根据数据子页面点亮对应 LED。传感器数值 `temp`、`level`、`vol`、`wt` 使用固定初值，因此本工程定位为多页面、矩阵键、RTC和Timer2任务状态训练，而不是传感器测量项目。

## 功能检查

- **问题**：综合界面看起来已经齐全，但功能完成范围容易被高估。
- **现象**：源码有多种显示页和参数操作；同时 `temp`、`level`、`vol`、`wt` 是固定初始值，`Logic_Task()` 将蜂鸣器、继电器保持为关闭状态。
- **原因**：这份代码首先搭起界面和任务组织，传感器通道使用固定输入，没有接入测量驱动。
- **处理**：项目按界面、RTC 与按键任务组织；传感器接入需要另行记录输入、显示和板端输出。
- **检查**：0 error / 0 warning 是历史构建记录，不替代板端功能检查。

用 Keil 打开 `16.uvproj`，核对 12 MHz、矩阵键盘接法和 DS1302，再按数据页、参数页、校准页的顺序检查。训练流程见 [蓝桥杯竞赛体系](../../../docs/蓝桥杯竞赛体系.md)。

这份工程把单模块代码放进多界面程序：用状态变量组织页面，用 Timer2 安排扫描和计数，用主循环处理按键、RTC 与输出逻辑。下一步按需求项补测量输入和板端验证。
