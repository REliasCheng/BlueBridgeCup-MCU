# 国赛方向训练：LED 模式、参数保存与状态调度

## 项目背景

这份综合训练工程围绕四种 LED 流转模式展开：按键设置运行间隔，ADC 决定亮度等级，参数写入 AT24C02，DS1302 提供时间，UART 输出当前配置。与单独点灯或读传感器的练习相比，重点是让多个输入、状态和输出在同一主循环中协同。

工程保留训练时的 C51 代码与 Keil 项目文件，重点记录模块间的资源分配。

## 硬件与功能

CT107D 板载 IAP15F2K61S2；`5.uvproj` 选择 `STC15F2K60S2 Series` 兼容目标，相关定时与串口配置按 12 MHz 编写。

| 资源 | 程序中的作用 |
|---|---|
| P0 + P2.5～P2.7 → 74HC138/74HC573 | 锁存 LED、继电器和数码管的位选/段选 |
| Timer2 | 约 1 ms 中断，执行数码管扫描、LED 软件 PWM 和 `Count[]` 任务计数 |
| P2.0/P2.1 软件 I²C | PCF8591 ADC 读取亮度输入；AT24C02 保存四种模式的运行间隔 |
| P1.7/P2.3/P1.3 | DS1302 的 SCK/SDA/RST，读取时分秒 |
| Timer1 + UART1 | 9600 bps 串口配置；`printf()` 经 `putchar()` 查询 `TI` 发送报告 |
| P3.0～P3.3 | 独立按键；其中 P3.0/P3.1 与 UART1 复用，使用时需核对板上连接 |

四种 LED 图案由 `Work_Mode[][]` 保存；每种模式的流转间隔可在 400～1200 ms 范围内按 100 ms 调整。ADC 值分为四个亮度等级，Timer2 中断以四步软件 PWM 控制 LED 亮灭。S6 进入/确认参数设置，S7 切换运行状态；非设置界面下 S5 触发串口报告，按住 S4 显示亮度等级。

## 软件设计与任务调度

```text
main → System_Init（模式表、EEPROM 参数、RTC、UART、Timer2）
     → Display_Task（设置页、时间页、亮度页）
     → Data_Task（分时写 EEPROM、读 ADC/RTC、发送串口报告）
     → Key_Task（按键事件、参数调整与界面切换）
     → Logic_Task（LED 图案、模式周期、闪烁与超时状态）

Timer2_Service（中断 12）
     → LED 软件 PWM / 锁存输出 → 数码管逐位扫描 → Count[0..8] 计数
```

`RunPeriod_Dsp[]` 是正在编辑的显示值，`Run_Period[]` 是运行时使用的参数。确认设置后，主循环按 `Flag_Save` 和地址逐项写入 EEPROM，而不是在按键分支中连续写完。RTC、ADC 和串口报告也留在主循环；中断主要负责必须周期执行的扫描、PWM 与计时。

## 核心代码入口

| 文件 | 重点 |
|---|---|
| `main.c` | 四种模式、界面状态、按键、任务计数、LED PWM 和串口报告 |
| `iic.c/.h` | 软件 I²C、`Read_Adc()`、`Read_Eeprom()`、`Write_Eeprom()` |
| `ds1302.c/.h` | 三线读写与 RTC 设时 |
| `uart.c/.h` | Timer1 波特率配置和查询式发送；此工程没有串口接收命令流程 |
| `library.c/.h` | Timer2 初始化和锁存操作 |
| `5.uvproj`、`STARTUP.A51` | Keil C51 工程与启动文件 |

从代码追 EEPROM 链路：启动时读取地址 1～4，检查间隔范围；设置页修改显示缓存，确认后同步运行参数，再由 `Data_Task()` 每隔约 5 ms 写一个地址。这个过程把非易失参数、界面编辑和实际运行状态分开了。

## 调试记录

代码检查发现，`I2CReceiveByte()` 的局部变量 `da` 在首次移位前没有初始化，可能影响 ADC 和 EEPROM 的读取；`System_Init()` 每次启动也会把 RTC 写成固定时间。调试时需要先确认读数、掉电参数和时间语义，再判断 LED 模式与串口报告是否正确。

复测按“设置间隔 → 断电重启 → 读取间隔”“改变 ADC 输入 → 观察亮度等级”“按键与 UART 切换 → 观察报告”记录输入和结果。源码保持训练时版本，驱动问题留待同条件实测后定位。
