# 省赛综合控制训练：ADC、温度与输出联动

## 项目背景

完成 PCF8591 模拟量采集、DS18B20 温度读取、独立按键、数码管显示和板载输出的单工程整合。单模块练习解决的是“能否读到数据”；这个工程进一步处理采样频率、显示刷新与控制逻辑如何同时运行。

工程对应省赛教材的综合练习，保留训练用 Keil 源码的原貌。

## 硬件平台与功能组成

开发板为 CT107D，板载 MCU 为 IAP15F2K61S2；Keil 工程 `4.uvproj` 选择 `STC15F2K60S2 Series` 兼容目标，Timer2 按 12 MHz 配置为约 1 ms 节拍。

| 资源 | 程序中的用途 |
|---|---|
| P0、P2.5～P2.7、74HC138/74HC573 | 共用数据与锁存通道；`0x80` 输出 LED，`0xA0` 输出蜂鸣器/继电器，`0xC0`/`0xE0` 控制数码管位选/段选 |
| P2.0 / P2.1 | 软件 I²C 的 SCL / SDA，读取 PCF8591 ADC |
| P1.4 | DS18B20 单总线数据脚 |
| P3.0～P3.3 | 4 个独立按键的输入 |
| Timer2 | 动态显示刷新，以及 ADC、温度和按键任务的计数节拍 |

数码管左侧显示温度、右侧显示电压，均按一位小数拆位；电压小数位映射到 LED 状态。温度高于代码设定的 `28.8` 时置位继电器输出；S4 按键切换蜂鸣器状态。这里描述的是源码规定的控制关系，实际温度和电压精度还取决于驱动时序及板端测量。

## 软件结构与任务调度

```text
main
  └─ System_Init：关闭初始输出、预读 ADC/温度、启动 Timer2
     └─ 主循环
        ├─ Display_Task：将 Volt/Temp 转成 8 位显示缓冲
        ├─ Data_Task：按计数周期读取 ADC 和温度
        ├─ Key_Task：读取独立按键，切换蜂鸣器状态
        └─ Logic_Task：计算 LED 映射和继电器阈值

Timer2_Service（中断 12）
  ├─ 锁存 LED、蜂鸣器/继电器状态
  ├─ 数码管关位 → 写段码 → 开当前位
  └─ 递增 Count_Adc / Count_Temp / Count_Key
```

`Data_Task()` 用约 150 个节拍更新 ADC、约 750 个节拍更新温度；`Key_Task()` 以节拍驱动 `Read_4Key()`，后者用连续计数确认一次按下。中断承担短而固定的输出与计数工作，采样和判断留在主循环，避免把 I²C 或单总线读数直接塞进显示扫描。

## 关键技术与代码组织

| 文件 | 作用 |
|---|---|
| `main.c` | 显示、采样、按键和输出逻辑；Timer2 中断入口 |
| `library.c/.h` | Timer2 初始化、`Read_4Key()` 与 `Control()` 锁存操作 |
| `iic.c/.h` | 软件 I²C 起始/停止、字节收发及 `Read_Adc()` |
| `onewire.c/.h` | DS18B20 单总线时序及 `Read_Temp()` |
| `4.uvproj`、`STARTUP.A51` | 原 Keil C51 工程及启动文件 |

`Logic_Task()` 先清 LED 状态，再按电压值的小数位选择输出；继电器由温度阈值单独控制，蜂鸣器由按键状态控制。这比直接在采样函数里改 P0/P2 更容易区分“输入数据”“业务判断”和“硬件输出”。源码保持原样复制，未为展示重写逻辑。

## 调试记录

本次整理对照了调用链，发现两个需要在板端测试前核查的点：

| 问题 | 代码现象与分析 | 核查方式 |
|---|---|---|
| ADC 接收值的有效性 | `I2CReceiveByte()` 的局部变量 `da` 在首次左移前未初始化；显示出数字不能证明读数正确 | 同时记录原始 ADC 字节、输入电压和显示值，再检查接收字节及换算 |
| 温度转换等待 | `Read_Temp()` 发出 `0x44` 后紧接着读取寄存器，没有单独等待转换完成 | 记录上电首值和连续读数，对照 DS18B20 转换时间检查采样时序 |

工程源码未因文档整理而修改，也没有把代码检查写成已完成的板端修复。用 Keil 打开 `4.uvproj` 时，先核对板型、时钟和按键/外设接线，再按“采样 → 显示 → LED/继电器/蜂鸣器输出”的顺序逐项验证。
